## 1. 총평

- **판정: 수정 후 착수.** 기술 조합을 재설계할 필요는 없으나, 현재 계획 그대로 전체 R1 구현을 시작하기에는 권한·금전 기록·알림의 계약이 부족하다.
- 비용 분리 저장과 실사용 중심 목표는 맞지만, 부모 개인 일정의 비공개 정책은 보안 규칙과 직접 충돌한다.
- 오프라인 납부와 트랜잭션, 자동 청구의 동시 생성·주기 변경, 부분 환불 완료를 먼저 정의해야 비용 현황을 신뢰할 수 있다.
- R1의 5주·50~75시간은 현재 범위 대비 낙관적이다. 핵심판과 완성판을 나누고, 실제 기기 푸시·배포 검증을 첫 단계로 당기는 것을 권한다.
- 착수 전 최소 조건은 지적 #1~#5의 설계 확정, 실제 결제 유형 확인, 요구사항별 구현·인수검사 매핑이다.

## 4. R1 범위 조정 의견

R1의 핵심 목표는 유지하되 **R1a: 가족이 실제 비용과 오늘 일정을 관리하는 핵심판 → R1b: 당초 R1 완성판**으로 나누는 것을 권한다. 아래 연기는 현재 요구사항의 승인된 변경이 아니며, 채택할 때 두 문서의 릴리스 표를 함께 바꿔야 한다.

### R1에서 반드시 넣어야 하는 것

- 가족 4계정과 서버 권한, 부모 개인 일정 공개범위, 형제 비공개. 사용자는 4명으로 제한해도 된다.
- 학원·수강 최소 정보, 오늘/주간 반복 일정, 이번 회차 휴강·보강, 자녀별 제외 기간.
- 가족의 실제 결제 유형에 맞는 자동 청구 1종부터 시작하고 나머지는 수동 청구로 지원. 건별 금액·기한 수정과 이력은 필수다.
- 납부 2탭, 부분납부, 해당 작업 취소, 환불 요청·분할 수령·잔액·종결, 종료 시 환불 안내.
- **기간과 무관한 처리 필요 목록**, 이번 달 청구 현황, 실제 입출금 기준 순지출, 간단 기타 지출.
- 온라인 금전 확정/실패 표시, 기본 중복 방지, 복원 가능한 JSON 백업, 보안 검사와 실제 폰 사용성 측정.
- 기본 납부·일정·환불 알림과 알림함. 핵심판 전에 4대 실제 설치·푸시 검증을 수행한다. 정시 알림이 미검증이면 “정식 R1”로 완료 선언하지 않는다.

기간은 확정치가 아니다. 현재 전체 R1에 대해 120~180시간을 범위 재산정의 출발점으로 제안한다. 개발만이 아니라 규칙·동시성·4대 실기기·실제 명세서 대조·복구 검증을 포함하고, R1a의 상세 작업 시간을 먼저 산정한다. AI 보조로도 실제 기기 승인·결제 정책 확인·가족 사용성 측정 시간은 줄이기 어렵다.
