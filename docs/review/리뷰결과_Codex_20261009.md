### R1a에서 반드시 유지/보완할 것

- D-07의 **엄마 주 사용자·가족 4명 폰+PC**를 유지한다. D-04의 로컬 저장 기본은 Q13 결정 전까지 기준으로 두며, 공유 방식을 Sprint 0 전에 정한다. 로컬 보기 모드는 화면 평가용이라고 명시한다.

82~124시간과 8~11주는 **조건부 목표**로 둔다. 실제 투입 주10~15시간의 전체 범위는 약5.5~12.4주이므로, 주차표는 고정 납기보다 예상 작업량으로 설명하는 것이 정확하다. 새로 커진 엑셀/안내형/복원 작업과 파일 공유 방식에 대한 스파이크 결과를 반영해 재산정한다. 별도의 근거 없이 또 다른 정확한 시간 추정치를 제시하지 않는다.

R1a의 성공 평가는 **엄마가 본인 iPhone에서 실제 입력을 계속하는지**를 중심으로 한다. 아빠·자녀·PC도 확정된 사용 기기다. 파일 공유 선택 시 다른 기기의 데이터가 최신이 아니거나 독립 입력이 제한되는 조건을 공개하고 평가한다. Spark 선택 시 가족 로그인·부모 비용 격리·형제 비공개·동시 입력 검증을 R1a 완료 기준으로 이동한다. 푸시 스케줄러·Blaze·AI 프록시까지 함께 당길 필요는 없다.

### 5.3 기술·법률 확인 경계와 저장 이력

- Expo static export + `/ai-note` 하위 경로는 가능한 방향이며 query-ID 상세경로로 기존 임의 동적 경로 문제를 줄였다. 파일 다운로드/복원·직접 새로고침·오프라인·SW 버전 교체는 S0 결과로 확정한다.
- iOS 웹 푸시는 홈 화면 앱과 사용자 동작 기반 권한 승인 조건이 있다. v1.1이 R1a의 서버 푸시를 제외한 것은 기술 제약과 일치한다. R1b 실제 수신 지연·거부·재등록은 기기에서 확인해야 한다. [WebKit 푸시 설명](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)
- Firebase Auth는 이메일+비밀번호 방향을 유지한다. Q13에서 Spark 공유를 선택하면 인증·가족 권한을 R1a로 이동한다. Spark는 결제정보 없이 시작할 수 있고 Firestore 무료 할당량이 있지만 한도/오류 처리가 필요하며, 정시 발송 함수는 별도 계획이다. [공식 요금제](https://firebase.google.com/docs/projects/billing/firebase-pricing-plans), [Firestore 할당량](https://firebase.google.com/docs/firestore/quotas). 이후 Google redirect를 추가하면 제3자 저장소 제한을 별도 검증한다. [공식 인증 지침](https://firebase.google.com/docs/auth/web/redirect-best-practices?hl=en)
- 교습비 반환의 경과 교습시간·사유 발생일·5일 참고는 공식 안내와 일치한다. 정확히1/3·1/2, 날짜 산입·월별 배분은 문서대로 원문/교육청 확인 후 F-12에 적용한다. 이번 리뷰에서 새 법률 해석을 확정하지 않는다. [공식 생활법령](https://www.easylaw.go.kr/CSP/CnpClsMain.laf?ccfNo=2&cciNo=3&cnpClsNo=2&csmSeq=1140&popMenu=ov)

[카카오 스킴](https://apis.map.kakao.com/android_v2/docs/api-guide/urlscheme/), [네이버 스킴](https://guide.ncloud-docs.com/docs/application-maps-url-scheme-vpc), [ODsay 운영정책](https://lab.odsay.com/doc/totalPolicy)

[Firebase 요금제](https://firebase.google.com/docs/projects/billing/firebase-pricing-plans), [Storage 조건](https://firebase.google.com/docs/storage/faqs-storage-changes-announced-sept-2024)
