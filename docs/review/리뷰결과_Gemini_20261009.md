### 2.2 ai-note에 도입해야 할 5대 핵심 지점 및 구체적 구현 방안

#### ① [하원나우 벤치마킹] 홈 화면 "Live 스케줄 및 카운트다운 카드" (R1a)
- **개념**: 오늘 일정 목록을 단순 나열하는 것에 그치지 않고, 현재 시각 기준 **[현재 진행 중인 수업]**과 **[다음 수업까지 남은 시간(분)]**, 그리고 **[등하교 후 학원 전 자투리 시간]**을 실시간 카드로 최상단에 브리핑합니다.
- **구현 방안**:
  - `domain/schedule.ts`에 `getLiveScheduleStatus(events: Event[], now: Date, memberId: string)` 순수 함수 작성.
  - 상태값 도출: `IN_CLASS` (수업 중, 종료까지 N분), `TRANSIT` (이동/대기 중, 다음 수업까지 N분), `FREE` (일정 종료).
  - 컴포넌트: `src/components/home/LiveStatusCard.tsx` (React Native Paper의 `Card`와 `ProgressBar` 활용, 1분 타이머로 상태 갱신).

#### ② [하원나우 벤치마킹] 자녀별 주간 시간표 카드 이미지 생성 및 카카오톡 원클릭 공유 (R1a 조기 구현)
- **개념**: 가족 단톡방이나 친척, 아이 본인에게 이번 주 시간표를 한눈에 볼 수 있는 깔끔한 이미지(PNG)로 캡처하여 전달하는 기능입니다.
- **구현 방안**:
  - 기존 계획(S-V5)에서는 R1b(Sprint 7)로 잡혀 있으나, 웹 환경에서는 서버 없이 `html-to-image` 라이브러리로 1~2일 만에 구현 가능합니다.
  - `src/components/schedule/WeeklyTimetableCapture.tsx`: 모바일 비율에 맞춘 인포그래픽 카드 뷰 렌더링.
  - 모바일 웹에서는 `navigator.share({ files: [blob] })` (Web Share API) 지원 기기에서 카카오톡으로 바로 공유, 미지원 기기는 이미지 다운로드 처리.

#### ③ [학원스케줄 벤치마킹] 일정 연동 "경량 준비물/가방 챙기기 체크리스트" (R1a)
- **개념**: R2의 거대한 숙제/할 일(Task) 기능 이전에, 자녀가 등교/학원 가기 전 교재·숙제장·필통 등을 챙겼는지 점검하는 경량 체크리스트입니다.
- **구현 방안**:
  - `Event` 모델의 `memo` 외에 선택적 필드로 `checklist?: { id: string; text: string; done: boolean }[]` 추가.
  - 자녀 보기 화면(S-V1, S-V4)에서 체크박스 토글 지원. 자녀가 폰을 열어 오늘 챙길 물건을 터치하면 완료 처리.

#### ④ [학원 고고 벤치마킹] "카드사별 교육비 실적 집계 및 한도 트래커" (R1a 비용 홈)
- **개념**: 학부모들이 학원비를 낼 때 가장 신경 쓰는 부분은 **"교육비 할인 카드 전월 실적(예: 30만 원, 50만 원)을 채웠는가?"**입니다.
- **구현 방안**:
  - `Payment` 기록 시 `cardName` (예: "신한 레이디클래식", "국민 노리2", "지역화폐") 입력 지원.
  - 비용 홈(화면 5)에 **[이번 달 결제수단별 지출]** 섹션 추가: 카드별 합계 금액 및 카드별 전월 실적 기준선 표시.

#### ⑤ [B2B 알림톡 연계] "알림톡/문자 영수증 원클릭 퀵 파서 (스마트 클립보드)" (R1a 신규)
- **개념**: 학원에서 카카오 알림톡이나 문자로 "[XX학원] 10월 원비 350,000원 결제 안내 https://pay.hakwon..."가 오면, 해당 텍스트를 복사한 뒤 앱에서 [클립보드에서 읽기] 버튼을 누르면 학원명, 금액, 납부링크가 폼에 자동 채워지는 기능입니다.
- **구현 방안**:
  - 복잡한 AI 호출 없이, 정규식 기반 파서(`domain/parsers/receiptParser.ts`) 구현:
    - 금액 패턴: `(\d{1,3}(,\d{3})*|\d+)원`
    - 링크 패턴: `https?:\/\/[^\s]+`
    - 학원명 매칭: 기 등록된 `Academy[]` 이름과 유사도 매칭.
  - 채팅 입력보다 훨씬 빠르고 실패 없는 학부모 친화적 입력 UX 제공.

## 5. R1 범위 조정 의견 (R1a / R1b 재조정)

1인 개발자(주 10~15시간)의 리소스 한계와 4인 가족의 실사용 지속성을 고려한 전략적 범위 재조정안입니다.

```
[기존 계획]
R1a: IndexedDB 단독 + 엑셀 + 복잡한 안내형 채팅 상태머신 -> 기기 간 실시간 공유 불가로 가족 실사용 실패 위험

[개선 권고안]
R1a: Firebase Spark(무료) 실시간 동기화 + 간편 폼 + 알림톡 퀵 파서 + 홈 Live 카드 + 시간표 이미지 공유
     (채팅 상태머신은 제외하고 실사용 킬러 피처에 집중!)
```

### 5.1 R1a에서 과감히 제외하거나 축소할 것
1. **안내형 대화형 입력 상태 머신 (I-21~I-27)**:
   - **이유**: 채팅 UI(말풍선, 되묻기, 취소 등)를 만드는 데 최소 15~20시간이 소요되나, 학부모는 폼 입력이나 알림톡 붙여넣기를 훨씬 편하게 여깁니다.
   - **조정**: 대화형 채팅 엔진은 R1a에서 제외하고, 단순 1단계 폼과 `I-04 퀵 파서`로 대체합니다.
2. **모바일 엑셀 가져오기 복잡도 축소**:
   - 엑셀은 PC 브라우저를 통한 초기 대량 등록 및 백업용으로만 한정하고, 모바일 화면에서의 복잡한 엑셀 편집/미리보기 기능은 최소화합니다.

### 5.2 R1a에 반드시 포함해야 할 것
1. **Firebase Spark 실시간 DB 동기화 (Q13 반영)**:
   - 엄마가 iPhone에서 등록한 학원비 납부/일정이 아빠와 자녀 폰에 3초 내로 동기화되어야 비로소 가족 앱으로서의 의미가 생깁니다.
2. **알림톡/문자 텍스트 퀵 파서 (I-04)**:
   - 학부모의 실제 결제 입력 시간을 '15초' 이내로 줄여주는 결정적 기능입니다.
3. **홈 Live 잔여시간 카드 및 주간 시간표 이미지 공유 (S-V1, S-V5)**:
   - 가족들이 앱을 열었을 때 "와, 정말 편하다"라고 느끼게 만드는 시각적 킬러 피처입니다.
4. **결제수단별(카드사별) 실적 트래커 (F-33)**:
   - 부모 입장에서 매달 가계 교육비 카드를 챙기는 실질적 유인을 제공합니다.
